# Развёртывание Sentinel 0.3

Нативная C++/Qt-консоль подключается к `siem-server` по взаимному TLS. Сервер хранит данные в PostgreSQL. `siem-agent` работает без GUI, получает политики и отправляет события. На ПК не требуется пароль PostgreSQL. Локальная SQLite агента — очередь доставки и контрольные точки, а не центральная SIEM-база.

## Быстрая проверка без изменения сети компьютера

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
python3 scripts/test-fleet.py
python3 scripts/test-update.py
```

Для интеграционной проверки нужны `openssl`, PostgreSQL server/client tools и Qt QPSQL/QSQLITE. Скрипт создаёт временные сертификаты, отдельный PostgreSQL на свободном loopback-порту, сервер и агент. Проверяет доставку, перезапуск с очередью, роли, конфликты политик, сканирование EICAR, отзыв устройства и вход desktop-консоли. Всё окружение удаляется. Настоящий firewall компьютера не изменяется.

## Сертификаты

Используйте отдельный сертификат для сервера, каждого администратора/аналитика и каждого компьютера. Приватные ключи не отправляйте в Git. Не распространяйте приватный ключ CA на сервер или агенты. Существующую корпоративную PKI также можно использовать: серверу нужен SAN с его DNS/IP и EKU serverAuth, клиентам — clientAuth.

Пример локальной PKI для пилота (все файлы в игнорируемом `.dev`):

```sh
python3 scripts/fleet-pki.py init-ca --ca-dir .dev/fleet-ca
python3 scripts/fleet-pki.py issue --ca-dir .dev/fleet-ca --output .dev/fleet/server --name server --server-name localhost
python3 scripts/fleet-pki.py issue --ca-dir .dev/fleet-ca --output .dev/fleet/admin --name admin
python3 scripts/fleet-pki.py issue --ca-dir .dev/fleet-ca --output .dev/fleet/pc-01 --name pc-01
```

Для сетевого развёртывания вместо `localhost` укажите фактическое DNS-имя сервера. Срок сертификатов — один год, CA — десять лет. Инструмент создаёт нешифрованные ключи с закрытыми правами доступа; для постоянной эксплуатации храните CA офлайн в защищённом хранилище. Автоматического продления сертификатов пока нет.

## Сервер и оператор

1. Создайте отдельную БД PostgreSQL и пользователя с правами на её схему. Внешний PostgreSQL по умолчанию подключается с `sslmode=verify-full`; задайте `database.sslrootcert` для его CA. Для локального loopback используется `prefer`.
2. Скопируйте `packaging/fleet/server.example.json` в приватную папку и заполните адрес БД и абсолютные пути `ca`, `certificate`, `private_key`, `database.password_file`. Для приёма удалённых ПК задайте `listen` на адресе сервера; пример по умолчанию слушает loopback.
3. Проверьте конфигурацию и зарегистрируйте сертификат оператора:

```sh
build/siem-server --config /absolute/path/server.json --check-config
build/siem-server --config /absolute/path/server.json \
  --add-operator /absolute/path/admin/identity.crt --name admin --role admin
build/siem-server --config /absolute/path/server.json
```

`--role analyst` разрешает просмотр и изменение статуса инцидентов. Только `admin` регистрирует устройства, меняет группы, политики и правила, отправляет задания и отзывает доступ. Аудит содержит SHA-256 сертификата исполнителя. Оператор и устройство не могут использовать одну идентичность.

Скопируйте `console.example.json`, заполните адрес сервера и пути к сертификату/ключу **оператора**:

```sh
build/sentinel-siem --fleet /absolute/path/console.json --theme night
```

В меню установленной Linux-версии есть **Sentinel — управление компьютерами**. `--fleet-connect` открывает выбор профиля. Старый режим прямого подключения к PostgreSQL сохранён для локальной диагностики, не предназначен для раздачи пользователям парка ПК.

## Подключение компьютера

В консоли: **Компьютеры → Подключить компьютер** → выберите публичный сертификат устройства → группу → сохраните одноразовый код. Код действует один час и привязан к конкретному сертификату. Повторный запрос того же уже зарегистрированного устройства безопасен; отозванное устройство не может повторно зарегистрироваться.

Заполните `agent.example.json`: `server` содержит адрес сервера и сертификат **устройства**, `enrollment_token_file` — файл кода, `state_dir` — отдельный закрытый каталог. На Windows используйте абсолютные Windows-пути и `scan_roots`, например `C:/Users`.

```sh
build/siem-agent --config /absolute/path/agent.json --check-config
build/siem-agent --config /absolute/path/agent.json
```

На Linux агент читает journald, на Windows — System/Application/Security через Windows Event Log API. Для полного доступа нужны соответствующие права службы. При первом старте собираются новые записи; затем используются сохранённые контрольные точки. Очистка/ротация системного журнала требует проверки контрольной точки и доступного периода хранения. UDP-syslog слушает только loopback, порт 5514. Для другого коллектора на том же ПК задайте свободный порт или `0`.

Очередь ограничена количеством событий и объёмом. По умолчанию — 100 000 событий / 256 МиБ полезных данных; файлы SQLite/WAL занимают дополнительное место. При переполнении системный источник приостанавливается, UDP-события могут теряться, счётчик отказов передаётся в состоянии. События удаляются из очереди только после подтверждения сервера. Сервер атомарно записывает событие и идентификатор доставки, предотвращая дубли после повторной отправки. Квитанции дедупликации пока сохраняются без автоматического удаления.

## Фоновая служба

После установки DEB/Arch-пакета:

```sh
sudo python3 /usr/share/doc/sentinel-siem/scripts/install-fleet-service.py agent /absolute/path/agent.json
# На машине сервера:
sudo python3 /usr/share/doc/sentinel-siem/scripts/install-fleet-service.py server /absolute/path/server.json
```

Скрипт проверяет конфигурацию, копирует ключи в закрытый каталог `/etc/sentinel-*`, включает и запускает systemd-службу. Сервер использует отдельного пользователя `sentinel-server`. Агент работает с ограничениями systemd и правами для чтения журналов/применения firewall. Пакет сам не запускает не настроенные службы и не перенастраивает NIC.

На Windows установите **машинный EXE из native MSVC/CPack** в Program Files, затем выполните в PowerShell администратора:

```powershell
& 'C:\Program Files\Sentinel SIEM\share\doc\sentinel-siem\scripts\install-service.ps1' `
  -Role agent -ConfigPath 'C:\secure\agent.json'
```

`-Role server` устанавливает серверную службу. Конфигурация и ключи копируются в ProgramData с ACL только для SYSTEM/Administrators. Настроен перезапуск при сбое. Portable/per-user MinGW-пакет предназначен для консоли; не запускайте привилегированную службу из пользовательского каталога.

Перед заменой установленного пакета остановите соответствующую службу и закройте GUI, затем после установки запустите службу. Для полного удаления службы: Linux — `systemctl disable --now sentinel-agent`; Windows — `Stop-Service SentinelAgent`, затем `sc.exe delete SentinelAgent`. Удаление пакета не должно уничтожать очередь/сертификаты. Автоматическая миграция установщика и автоматическое обновление всего парка пока не реализованы.

## Политики и антивирус

В **Политиках** создайте пилотную группу, откройте настройки и задайте firewall/расписание проверки. Встроенный редактор NGFW сохраняет отдельные профили Linux/Windows/DPDK. Номер версии защищает от перезаписи изменений другим администратором. В разделе компьютеров назначьте группу устройству.

`manage_firewall` по умолчанию выключен. Включайте его в локальной конфигурации агента только после проверки профиля: агент управляет собственными таблицами/правилами Sentinel и считает начальной базой пустую политику Sentinel. Если раньше правила Sentinel применялись из локальной консоли, согласуйте/перенесите их перед первым управляемым применением. Чужие таблицы не очищаются.

Новая политика сохраняется на диск до применения. Отдельный процесс ожидает подтверждения связи от сервера; при отсутствии подтверждения через 90 секунд восстанавливает предыдущую подтверждённую политику. Незавершённое применение восстанавливается также после перезапуска; при штатной остановке агента выполняется откат. На Linux подтверждённые правила повторно применяются при запуске службы. Ошибки применения/отката показываются в состоянии устройства. Это не проверка доступности всех бизнес-сервисов и не аппаратный fail-open. Действующие ограничения backend перечислены в [NGFW.md](NGFW.md).

Реальная проверка отката выполняется только в отдельном сетевом namespace:

```sh
bash scripts/test-firewall-container.sh
```

Агент проверяет только пути, разрешённые локальным `scan_roots`. Политика задаёт папки, исключения и период от 5 минут. **Проверить антивирусом** создаёт сохраняемое на сервере задание; его результат виден в **Заданиях**, обнаружения — в событиях/инцидентах. Требуются отдельно установленный ClamAV и обновление баз freshclam. Без ClamAV EICAR/SHA-проверка не объявляется полной антивирусной проверкой. Удалённое автоматическое удаление файлов не выполняется.

DPDK/VPP остаются отдельными Linux-сетевыми компонентами. Endpoint-агент пока не запускает DPDK/VPP и не применяет их политики; DPDK-профиль в редакторе сохраняется для шлюза, настройка/запуск выполняется через локальную консоль. VPP ACL, TCP reassembly, TLS-inspection, VPN, kernel on-access AV и защита процессов ещё не реализованы.

## Хранение, резервные копии и обновления

Сервер выполняет SQL в отдельном потоке, поддерживает ограниченные очереди запросов и повторное подключение к PostgreSQL. Миграции записываются в `schema_migrations`. Раз в минуту удаляется до 1000 событий старше `retention_days` (90 по умолчанию); события, связанные с инцидентами, сохраняются. Аудит, инциденты и квитанции не удаляются автоматически. Нагрузочные пределы на большом парке ещё не измерены.

Используйте штатные `pg_dump -Fc` / `pg_restore`, перед миграцией делайте проверенную резервную копию. JSON/CSV из интерфейса не заменяют резервную копию. Храните копии вне Git; настройте расписание и проверьте восстановление на отдельной БД.

Для проверки происхождения пакетов добавлены `scripts/sign-release.py` и `siem-update-verify`. Подпись — RSA/SHA-256; открытый ключ доверенного издателя задаётся локально. Проверяются подпись манифеста, размер/SHA-256 пакета, платформа, срок действия и монотонный номер выпуска:

```sh
python3 scripts/sign-release.py dist/deb/PACKAGE.deb \
  --private-key /offline/release.key --version 0.3.0 --sequence 1 --platform linux-x64
build/siem-update-verify --manifest PACKAGE.deb.manifest.json \
  --signature PACKAGE.deb.manifest.json.sig --public-key /trusted/release.pub \
  --package PACKAGE.deb --minimum-sequence 0
```

Ключ подписи выпуска должен отличаться от CA/агентских ключей. `--minimum-sequence` задаётся оператором из защищённого учёта установленных выпусков. Проверяйте и устанавливайте из каталога, недоступного для записи обычным пользователям. Проверяющий инструмент ничего не устанавливает; автоматического обновления, автоматического отката пакета и Windows Authenticode-подписи ещё нет. Настоящие ключи издателя не создаются и не публикуются автоматически.

## Git и секреты

```sh
python3 scripts/check-secrets.py --working-tree
python3 scripts/check-secrets.py
git config core.hooksPath .githooks
```

Проверка фиксированной версией Gitleaks с проверкой SHA-256 скрывает найденные секреты в выводе. Локальные hooks блокируют коммит/push при находках; Actions дополнительно проверяет всю историю и запрещённые пути. Для нового клона hooks нужно включить указанной командой. Генерируемые ключи, `.env*`, локальные JSON, базы, `.dev`, `build*` и `dist` исключены из Git/контекста Docker. В Git должны быть исходники, примеры без секретов, документация и тесты.
