# Проверки сборки и сетевых модулей

## Воспроизводимые сетевые тесты

```bash
python3 scripts/test-dpdk.py
bash scripts/test-firewall-container.sh
```

Второй тест использует образ `sentinel-siem-deb:local`, созданный `scripts/package-deb.sh`.
Если сеть недоступна и этого образа ещё нет, на Linux доступен офлайн-вариант:

```bash
bash scripts/test-firewall-container.sh --host-runtime
```

Он использует уже загруженный образ `python:3.12-slim` и монтирует системный `/usr`
и каталог `build` **только для чтения**. Тест выполняется в отдельном сетевом
пространстве Docker с `--network none`, `--cap-drop ALL --cap-add NET_ADMIN --cap-add NET_RAW`.
Сетевые интерфейсы, namespace и firewall хоста не используются и не изменяются.
Запускать этот скрипт через `--network host` не требуется.

Проверенные сценарии:

- DPDK PCAP PMD читает три настоящих Ethernet/IP/TCP-кадра, обнаруживает SQLi и XSS;
  пассивный монитор не блокирует и не пересылает пакеты.
- Два PCAP PMD в inline пересылают только один безвредный кадр и отбрасывают два
  кадра с HTTP-сигнатурами. Проверяются реальные TX PCAP, включая содержимое кадра.
- Forward-правило TCP/80 отбрасывает все три кадра; TX-файлы пусты.
- Firewall helper применяет nftables-политику, после чего UDP-пакет не приходит
  локальному получателю, а счётчик правила увеличивается.
- Инъекция в поле адреса отклоняется до применения; текущая политика сохраняется.
- Пустая политика восстанавливает доставку. Посторонняя таблица nftables остаётся
  неизменной во всех сценариях.

Эти тесты прошли на Linux/CachyOS с Qt 6.12 и DPDK 25.11.3. Они не подтверждают работу с физическими NIC и линейную производительность. Отдельные проверки VPP и Windows описаны ниже.

## Сборка Debian при недоступном основном зеркале

Для текущего окружения основной `deb.debian.org` отвечает ошибкой TLS/тайм-аутом.
Проверенный доступный путь загрузки зависимостей:

```bash
SIEM_DEB_BASE=python:3.12-slim \
SIEM_DEBIAN_MIRROR=https://mirror.yandex.ru/debian \
bash scripts/package-deb.sh
```

Локальный `python:3.12-slim` основан на Debian 13. Проверка подписей Debian APT
остаётся включённой; зеркало не добавляется к конфигурации хоста. Опция зеркала
применяется только к Debian-образам с `/etc/apt/sources.list.d/debian.sources`.
Сетевые попытки APT ограничены тайм-аутом и завершают сборку при ошибке обновления.

DPDK загружает PCAP PMD динамически, поэтому Docker-сборка отдельно добавляет
пакет `librte-net-pcap` соответствующей ABI-версии в зависимости `.deb`.
Аппаратные PMD для конкретных сетевых карт устанавливаются отдельно.

## Готовые пакеты и проверки runtime

- Собран `.deb` для Debian 13 amd64, Qt 6.8.2 и DPDK 24.11.4. Проверены установка
  через `dpkg`, запуск установленного `/usr/bin/sentinel-siem` и DPDK PCAP/inline
  у установленного сенсора. Правила nftables проверены в отдельном контейнере.
- Собран пакет Arch/CachyOS x86_64 через makepkg; сборка и встроенные тесты прошли.
- Собраны настоящие Windows PE x64 бинарники, NSIS EXE и portable ZIP через
  MinGW/Qt 6.12.0. Qt-плагины, libpq и транзитивные runtime DLL включены в поставку,
  вместе с лицензиями и манифестом версий/хешей.
- Под Wine прошли 8 проверок C++-ядра; два теста с внешними Linux-сервисами
  пропущены. Отдельно Windows GUI подключился через QPSQL/libpq к настоящему
  PostgreSQL с SCRAM-паролем и открыл все страницы.
- Под Wine проверены установка EXE в каталог с пробелом, запись UninstallString,
  запуск установленного GUI и удаление. Деинсталлятор удаляет только файлы
  поставки и сохраняет посторонний файл пользователя в каталоге установки.
- Настоящий ClamAV проверен в одноразовом контейнере безопасной пользовательской
  сигнатурой, которую встроенный EICAR/SHA-256 сканер не распознаёт. Детекция,
  имя файла с пробелами и SHA-256 результата проверены. Команда:
  `bash scripts/test-clamav-container.sh`.
- `scripts/run-local.sh` проверен с отдельным приватным PostgreSQL-кластером,
  loopback-подключением и сгенерированным SCRAM-паролем. Системная служба не меняется.

Wine не заменяет испытания на нативной Windows: UAC, COM Firewall enforcement,
обновление и удаление при открытом GUI требуют Windows-стенда. Установщик не
подписан. Физические NIC, hugepages и реальные скорости не проверялись;
в UI отсутствующие подключения отображаются как недоступные.

## Обновление: ночная тема и политики NGFW v2 (29 октября 2026)

- Qt: переход по всем страницам в светлой и ночной теме, сохранение и повторное открытие независимых профилей, ввод правила через настоящий диалог, проверка тёмной палитры.
- PostgreSQL: корреляция, сохранение и экспорт, атомарное compare-and-set профилей; устаревшая версия не перезаписывает более новую.
- Linux nftables: порты источника и диапазоны назначения; реальная UDP-блокировка; rate limit; сохранение established TCP при default-drop и блокировка нового соединения; реальный SNAT источника и DNAT порта входящего кадра через veth. Проверки только в отдельном контейнере с NET_ADMIN/NET_RAW.
- DPDK: старый JSON и новый профиль; отключение HTTP-проверки; alert-only; отдельная SQL-сигнатура; forward default-drop; диапазоны портов; HTTP Host. Все сценарии проверяют реальные TX PCAP побайтно.
- VPP v25.10 собран из официальных исходников в `.dev/vpp-build`, без системной установки и подключения NIC. `scripts/test-vpp.sh` проверил pg0 RX=3 / pg1 TX=3 и побайтовое совпадение выходных кадров. Трассировка в этом лабораторном сценарии отключена: с данным VPP/Clang она вызывала сбой; пересылка проверяется непосредственно по выходному PCAP.
- Windows: обновлённые C++-тесты и редактор профилей проходят под Wine; ночная тема и обход страниц также проверены. Применение COM/UAC требует проверки на настоящей Windows.

Команды для повторения VPP, включая проверку GUI: [NETWORK_LAB.md](NETWORK_LAB.md). Возможности и ограничения каждого backend: [NGFW.md](NGFW.md).
