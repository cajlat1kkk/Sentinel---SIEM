# Sentinel SIEM — нативное desktop-приложение

C++20 / Qt 6 Widgets, **PostgreSQL** для рабочих данных. Интерфейс на русском: светлая поверхность, скруглённые карточки, чёрная навигационная капсула и две палитры — Ember (оранжевая) и Flow (лавандовая). Переключатель находится внизу окна; в рабочем режиме выбор сохраняется. Приложение запускается отдельным нативным процессом: Electron, браузер, JavaScript, Python backend и HTTP-сервер не используются.

Рабочий MVP для лабораторной эксплуатации: сбор и поиск событий, корреляция, расследования, антивирусная проверка, карантин, сетевые политики, нативный DPDK-сенсор и получение состояния VPP. Границы сетевой и антивирусной защиты перечислены ниже: это не замена промышленному EDR/NGFW.

## Быстрый запуск на текущей машине

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
./build/sentinel-siem --demo
# Альтернативная палитра из первого референса:
./build/sentinel-siem --demo --theme flow
```

`--demo` показывает изолированные примеры событий во временной SQLite. PostgreSQL не требуется, тестовые данные удаляются при выходе. В деморежиме применение firewall к ОС отключено. Службы DPDK/VPP и антивирус не изображаются работающими без реального подключения.

Для работы с настоящей локальной PostgreSQL без Docker и ручной настройки:

```bash
bash scripts/run-local.sh
# Остановить только частный сервер этого проекта после закрытия приложения:
bash scripts/stop-local-db.sh
```

Локальный launcher создаёт отдельный кластер в `.dev/postgres`, случайный пароль в `.dev/postgres-password` с правами владельца и БД `sentinel`. Сервер слушает только `127.0.0.1:55440` (порт можно задать через `SIEM_LOCAL_PG_PORT`). Системная служба PostgreSQL не меняется, данные сохраняются между запусками. Это окружение разработки; для развёртывания используйте отдельную БД и ограниченного пользователя. Требуется установленный PostgreSQL server.

Обычный запуск открывает диалог PostgreSQL:

```bash
./build/sentinel-siem
```

Подготовка базы через Docker Compose (контейнером является только PostgreSQL, не desktop-приложение):

```bash
read -rs -p 'PostgreSQL password: ' SIEM_DB_PASSWORD; echo
export SIEM_DB_PASSWORD
docker compose -f packaging/compose.yaml up -d
./build/sentinel-siem --connect-env
```

Параметры по умолчанию: `127.0.0.1:5432`, база `sentinel`, пользователь `sentinel`. Приложение создаёт таблицы при первом подключении. Можно использовать уже существующий PostgreSQL 14+ с отдельной базой и пользователем, имеющим права DDL/DML в ней.

Переменные подключения: `SIEM_DB_HOST`, `SIEM_DB_PORT`, `SIEM_DB_NAME`, `SIEM_DB_USER`, `SIEM_DB_PASSWORD`. Без `--connect-env` значения заполняют диалог, где их можно изменить. Пароль не сохраняется в QSettings и не передаётся аргументом командной строки. Параметры TLS libpq доступны через стандартные переменные `PGSSLMODE`, `PGSSLROOTCERT` и другие. Для удалённой БД настройте `verify-full` и доверенный сертификат.

| События | Syslog UDP на `127.0.0.1:5514`, RFC5424, обычные строки, JSONL и Suricata EVE, поиск, фильтр приоритета, просмотр исходных данных, CSV |

### Проверка сценария SIEM

1. Импортируйте `samples/events.jsonl` в разделе «События».
2. В «Инцидентах» появятся подбор пароля и тестовая Suricata-детекция.
3. Откройте инцидент, измените статус и добавьте заметку.
4. В «Настройках» запустите syslog-коллектор. Пример отправки с Linux:

```bash
logger --udp --server 127.0.0.1 --port 5514 'Failed password for invalid user test'
```

Коллектор слушает только loopback, не публикует неаутентифицированный сетевой приёмник. Для удалённых узлов используйте rsyslog/syslog-ng с TLS и локальной пересылкой. Поддержка RFC3164 ограничена сохранением строки и PRI; RFC5424 также извлекает hostname и timestamp.

### Антивирус

Установите ClamAV и обновите базы его штатным `freshclam`. При наличии `clamscan` приложение дополнительно запускает полноценную проверку ClamAV. Ошибки отсутствующих/устаревших баз показываются в результате, а не считаются успешной проверкой.

Без ClamAV работают только безопасная тестовая EICAR-сигнатура и импортированные SHA-256. Формат файла сигнатур: `64-символьный SHA256` и необязательное название через пробел. Импортированные хеши действуют до закрытия приложения.

Встроенный сканер читает файлы до 256 МБ, пропускает символические ссылки, не распаковывает архивы. Архивы обрабатывает ClamAV в рамках его лимитов. Карантин создаёт копию, проверяет её SHA-256 и только затем удаляет исходник. Если удаление не удалось, запись помечается `copy`, а не `isolated`. Восстановление не перезаписывает существующие файлы. Данные карантина находятся в пользовательском каталоге приложения, а метаданные — в PostgreSQL. На Linux файлы карантина доступны владельцу без бита исполнения; криптографического шифрования карантина нет.

Наблюдение за папкой использует QFileSystemWatcher и реагирует на изменения её непосредственного содержимого. Оно не обеспечивает файловый перехват в ядре, защиту процессов или полноценный on-access антивирус.

### DPDK и VPP

Без оборудования можно открыть `samples/http-lab.pcap` в разделе сетевого движка. Это три синтетических HTTP-пакета с корректными контрольными суммами. Сенсор читает файл через настоящий DPDK PCAP PMD:

```bash
./build/siem-dpdk --pcap "$PWD/samples/http-lab.pcap" --seconds 2
```

Для живого трафика нужны подходящие сетевые порты, драйверы, hugepages и права. Параметры EAL задаются пользователем. Приложение не отвязывает сетевые карты от ОС и не меняет hugepages автоматически. Нужен отдельный SPAN/TAP-порт для пассивного сенсора; чтение RX-пакетов потребляет их.

```bash
# Только на подготовленном лабораторном хосте:
./build/siem-dpdk --seconds 60 -- -l 0 --no-telemetry -a 0000:03:00.0
# Два выделенных порта, JSON-политика экспортирована из приложения:
./build/siem-dpdk --inline --policy policy.json -- -l 0 --no-telemetry -a 0000:03:00.0 -a 0000:03:00.1
```

Inline пересылает кадры между двумя портами. Использует включённые `forward`-правила по порядку и блокирует распознанные HTTP-сигнатуры. Политика — снимок на момент запуска, после изменения её нужно перезапустить. При остановке процесса пересылка прекращается. В режиме мониторинга ничего не блокируется. События ограничены 500/сек, полный счётчик пакетов сохраняется; `suppressed` показывает число неэкспортированных записей.

Сенсор не собирает TCP-потоки/IP-фрагменты, не дешифрует TLS, не распознаёт все приложения и обходы сигнатур. IPv6 extension headers не разбираются. Некорректные и не-IP кадры не имеют L7-анализа. Это ограниченный сетевой MVP, а не промышленный DPI.

VPP устанавливается и запускается отдельно. Укажите его CLI-сокет, обычно `/run/vpp/cli.sock`, и нажмите «Получить состояние». Требуются `vppctl` и доступ к сокету. Адаптер VPP получает телеметрию, не устанавливает ACL в VPP. Один PCI-порт нельзя одновременно отдать VPP и отдельному DPDK-сенсору. Windows-версия GUI работает без локального DPDK/VPP dataplane; сенсор этой реализации собирается для Linux.

### Правила ОС

Linux helper сначала выполняет `nft --check`, затем атомарно загружает транзакцию только в `inet sentinel_siem`. Остальные таблицы и политика ОС не очищаются. Базовая политика цепочек — accept; drop-правила применяются дополнительно к действующему firewall. Accept в собственной таблице не отменяет drop в другой таблице. Правила не автоматически сохраняются после перезагрузки ОС.

Windows helper использует COM `INetFwPolicy2` / `INetFwRule`, управляет именами `SentinelSIEM-*`, не меняет профили и глобальные политики. Поддержаны input/output и TCP/UDP/any; forward/ICMP отклоняются. Блокирующие правила Windows имеют приоритет над разрешающими. Обновление Windows Firewall не атомарно; ошибка требует проверки и повторного применения/отката. Helper запускается через UAC.

Рабочая консоль не требует root. Linux запрашивает повышение прав через polkit только при явном применении правил. Текущий UI-статус «Применялось» означает сохранённый результат операции; это не непрерывная проверка актуальных правил ОС.

## Сборка и пакеты

Зависимости: CMake 3.24+, компилятор C++20, Qt 6.4+ Core/Widgets/Network/Sql/Concurrent/Test, плагины QPSQL/QSQLITE, PostgreSQL client libraries. На Linux DPDK определяется через pkg-config. Чтобы явно исключить сенсор: `-DSIEM_WITH_DPDK=OFF`.

Arch/CachyOS:

```bash
sudo pacman -S --needed base-devel cmake ninja qt6-base qt6-svg postgresql-libs dpdk
bash scripts/package-arch.sh
sudo pacman -U dist/arch/sentinel-siem-0.2.0-1-x86_64.pkg.tar.zst
```

Debian/Ubuntu: `.deb` необходимо собирать на целевом базовом дистрибутиве, а не из Arch-бинарников:

```bash
bash scripts/package-deb.sh  # по умолчанию Ubuntu 24.04 через Docker
# другая базовая система, например Debian 13:
SIEM_DEB_BASE=debian:13-slim bash scripts/package-deb.sh
sudo apt install ./dist/deb/sentinel-siem-0.2.0-Linux.deb
```

Пакеты динамически зависят от библиотек соответствующего дистрибутива. PostgreSQL server, ClamAV и VPP устанавливаются отдельно. Для запуска на текущем Arch/CachyOS также доступен обычный исполняемый файл `build/sentinel-siem` с системными Qt-библиотеками.

Windows 10/11 x64: сборка на Windows из Developer PowerShell Visual Studio 2022, Qt 6.8 MSVC, CMake, Ninja, NSIS, PostgreSQL client DLL:

```powershell
# Добавьте Qt bin и NSIS в PATH; укажите PostgreSQL bin при необходимости:
$env:SIEM_PG_RUNTIME_DIR = 'C:\Program Files\PostgreSQL\17\bin'
./packaging/windows/build.ps1
```

На Windows этот путь создаёт установщик в `build-windows/` через CPack/NSIS. Есть CI для Linux/Windows: `.github/workflows/build.yml`.

В этом окружении также выполнена настоящая кросс-сборка MinGW/Qt 6.12 с runtime-пакетами MSYS2:

```bash
bash packaging/windows/cross-build.sh
```

Нужны MinGW x86_64, нативные Qt 6.12 host tools, CMake/Ninja, Python 3, tar/zstd и Wine. Версии/хеши загрузок закреплены в `packaging/windows/msys2-packages.lock.json`; пакеты не устанавливаются в систему. Результаты в `dist/windows/`: EXE-установщик, portable ZIP и распакованная папка. Лицензии и manifest runtime включены в поставку. Проверка под Wine подтверждает базовую работоспособность сборки, но не заменяет проверку UAC, COM Firewall и GUI на нативной Windows.

## Тестирование

```bash
ctest --test-dir build --output-on-failure
bash scripts/test-postgres.sh  # отдельный временный PostgreSQL, очищается после проверки
QT_QPA_PLATFORM=offscreen ./build/sentinel-siem --demo --screenshot /tmp/sentinel.png
```

Тесты проверяют сохранение данных, порог корреляции, UDP, импорт, нормализацию EVE/syslog, отклонение инъекций в firewall-политике, пакетный анализ, EICAR/SHA-256, карантин, восстановление, изменённый файл и PostgreSQL. Smoke-тест открывает все десять разделов. Для DPDK есть `scripts/test-dpdk.py`, для nftables — `scripts/test-firewall-container.sh` в изолированном network namespace контейнера. `scripts/test-clamav-container.sh` проверяет настоящий ClamAV с безопасной локальной тестовой сигнатурой в отдельном контейнере; она не подменяет официальную базу на хосте.

## Эксплуатационные границы

- 1 000 последних строк в таблицах событий/инцидентов/активов; CSV экспортирует показанную выборку. JSON ограничен 100 000 строк на таблицу и содержит явный `row_limit_per_table`.
- Импорт журнала: до 20 МБ, строка до 64 КБ, текст события до 16 КБ.
- PostgreSQL обслуживается отдельно: резервные копии через `pg_dump`, ротация/retention и TLS на стороне администратора. Встроенного удаления старых событий нет.
- SIEM — консоль одного доверенного аналитика без RBAC, multi-tenant изоляции и неизменяемого audit. UDP не гарантирует доставку.
- Параметры ОС, правила firewall и локальный карантин относятся к конкретному компьютеру. Не используйте одну рабочую БД для независимого управления несколькими endpoint без отдельного разбиения.
- Реальный VPP, физические NIC/hugepages, производительность на линии и Windows требуют отдельного стенда. Показатели Gbps/latency из дизайнерского примера не подставляются как реальные.
